Help · v1.2.0

What this is

A replacement for the Freshdesk overview. It reads two live sources every time it opens: the Pipedrive Support pipeline (tickets) and email threads sent or copied to support@target3d.co.uk. Nothing is typed in by hand. The Sources strip at the top shows where every number comes from, when it loaded, and lets you refresh a source or download it as CSV.

Pipedrive section

  • Open tickets: deals in the Support pipeline with status Open, in any stage.
  • Opened / Closed (30 days): tickets created, or marked Won, in the last 30 days. Won is treated as “closed”.
  • In RMA: open tickets in the “RMA – In progress” stage.
  • Complete, not closed: open tickets sitting in “Support complete – For review”. These usually only need a final check and marking as Won.
  • Idle 14+ days: open tickets whose Pipedrive record hasn't been edited for 14 days or more. Emails logged against a deal do count as edits.
  • Age: days from creation to today (open) or to the close date (closed). Idle: days since last edit; only for open tickets.
  • Customer emailed last / Last email · From: uses the emails linked to each ticket in Pipedrive (including the support@ team inbox, once an email is linked to the deal). “Customer” means the latest linked email came in rather than went out, so a reply is probably owed. Replies sent from a mailbox that isn't synced to Pipedrive aren't counted, so a ticket can show “Customer” even though someone answered. Link or BCC replies to keep it accurate. Emails not linked to any deal aren't visible here.
  • Came in via: Pipedrive's source channel, e.g. Jotform for the support form, Manual for tickets created by hand.

support@ section

  • Search used: (to: OR cc: OR deliveredto: support@target3d.co.uk) newer_than:120d, excluding “Out of Office” subjects, up to 50 threads.
  • Last word was theirs / Next move: Ours: the latest message in the thread came from an address outside target3d.co.uk.
  • In the Nucleus the server reads every message in each thread, so the true latest message is always known. Threads to open only counts threads whose messages couldn't be read.
  • Unread reflects the read state in the support@ inbox the Nucleus reads (the account the administrator connected), not your own mailbox.
  • Vendor escalations sent directly to individuals (e.g. OptiTrack, 7thSense, 4DViews support) won't appear unless support@ was copied.

Using it

  • Click a stage bar to filter the ticket list to that stage; click the stage chip to clear it.
  • Click any column header to sort; type in the search box to filter rows.
  • The Pipedrive figures are read as you, with the API token you signed in to the Nucleus with, so you need access to the Support pipeline. The support@ inbox is read once for everyone by the Nucleus server.
  • Open Sources at the top to refresh a source or download it as CSV.

Tips for cleaner numbers

  • Copy support@ on every customer-facing support reply so the inbox view stays complete.
  • In Pipedrive's team inbox, link each support email to its ticket (or create a ticket from it). Unlinked emails don't count towards reply tracking.
  • Move tickets out of “For review” promptly (mark Won) so open counts reflect real work.
