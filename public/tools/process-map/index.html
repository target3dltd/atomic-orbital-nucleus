The five phases every project uses

The rules

  1. No deal, no project.Every project links to a Pipedrive deal. Support and RMA Jotforms already create the deal automatically; everything else needs the deal first.
  2. One project per piece of work.A health check, a demo and a proof of concept on the same deal are three linked projects, not one long one. Each has its own template, owner and close-out.
  3. Same five phases for everything.Request, Plan, Prepare, Deliver, Close. Status is always reported as type · phase.
  4. One named owner.Each project has one person accountable for moving it to the next phase, even when several teams do the work.
  5. Unpaid work is an approved investment.Proof-of-concept and technical engineering work needs written success criteria and MD sign-off before it starts, and is capped at one day (£450 at the internal run rate). Anything beyond that is quoted as paid work or re-approved. Effort is logged even when nothing is billed.
  6. Every project reports back to the deal.The close-out report goes on the deal and sets the next action: another project, a quote or tender, won, or lost.
  7. Price before you win.Paid work is priced in a QUOTE or TENDER first. A deal is only marked won once one is accepted, and that is what starts the Deliver projects. In-SLA support and warranty RMAs are the exception.

Naming and IDs

Uses the existing ID-ClientName-Type pattern. The Type part always comes from the code table below, so names stay consistent and any folder, chat space or invoice traces back to its deal.

Project ID
{ID}-{ClientName}-{Type}

e.g. 4127-AutoLab-DEMO-ON. A second demo on the same deal adds a number: 4127-AutoLab-DEMO-ON-2.

Drive folder
/PROJECTS/{ID}-{ClientName}-{Type}/

Uses the existing folder template from the Studio delivery process (00_DOCUMENTS, 01_DATA …).

Pipedrive project
{ID}-{ClientName}-{Type}

Same name as the folder. Created from the type's template and linked to the deal, so it shows on the deal's timeline.

To confirm before roll-out

Assumptions in this version that need a decision.

  • Type codes. Approve the first code table (HEALTH, DEMO-ON, DEMO-OFF, SURVEY, TECH, INSTALL, SHOOT, TRAIN, SUPPORT, RMA) or rename any before templates and folders use them.
  • Does the 1-day cap apply to demos? Technical Engineering is capped at one day (£450). Should demos on prem and on location have the same cap, or stay uncapped cost of sale?
  • One form, not two. Site visit and health check can be logged in the System Designer or on Jotform. Pick one so the data isn't entered twice.
  • Tools to Pipedrive. Should System Designer, licence tracker and SOW Builder outputs land on the deal automatically (BCC email or Drive folder), the same way the Jotforms do?
  • Price and bid sign-off. Quote price sign-off and the tender bid / no-bid decision are shown as Sales with the MD. Confirm who signs, and whether small quotes need sign-off at all.
  • Tender library. Where reusable tender answers, case studies, CVs and certificates live, and who keeps them current.
  • Quote and Tender templates. Both need a Pipedrive project template; tenders also need a compliance matrix template.
  • New templates needed. Pipedrive project templates and a request Jotform for Demo Offsite and Technical Engineering; a template for Health Check if one doesn't exist yet.

Help

Reading the map

  • Start at Lead and Deal. Nothing happens without a deal in Pipedrive.
  • The diamond is the question asked at every review: what does this deal need next? The answer is one of the project types in the coloured tracks.
  • Prove (amber) runs while the deal is open. Deliver (teal) starts when the deal is marked won. Support (violet) is for existing customers.
  • Click a project box to open its detail. Steps marked Gate need a decision before the project continues. Steps marked NEW don't exist in the current process yet.
  • The dashed line shows each project's close-out feeding back to the deal, where the next action is set.

Finding a step

  • Type in the Find box above the map, e.g. calibrate, SOW, invoice, or a role such as Accounts. Matching projects stay bright on the map and every matching step is listed with its phase.
  • Click a result to open that project with the matching steps highlighted. Press Esc to clear the box, or / anywhere to jump to it.

Moving around

  • The bar under the title jumps to each section and stays at the top as you scroll.
  • In Project detail, use the ← and → buttons or the arrow keys to step through every project type in order.
  • "Often leads to" at the bottom of each project links to the projects that usually come next.

Quote or Tender?

  • Quote: the client asked us directly for a price. We design, cost and send a quote with an SOW.
  • Tender: a formal competitive bid with fixed deadlines, compliance questions and scoring, often on a portal. It starts with a bid / no-bid decision.
  • Both sit at the end of Prove. A deal is marked won only once one is accepted, and that starts the Deliver projects.

Linking to one project

  • Every project type has its own link. Add #demo-onsite, #tech-engineering, #install, #quote, #tender and so on to the page address to open straight at that project.
  • Use these links from the Operations Google Site, so each process page points at its part of the map.
